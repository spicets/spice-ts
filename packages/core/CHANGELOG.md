# @spice-ts/core

## 0.4.0

### Minor Changes

- dc7cc4a: BSIM3 (LEVEL=8/49): `VERSION=3.2.x` cards now simulate with the ngspice-47 bsim3v32 revisions (3.2, 3.2.2, 3.2.3, 3.2.4, selected like b3v32set.c, including LMLT) instead of failing with `UNSUPPORTED_MODEL_VERSION` (#594); 3.0/3.1 are still rejected. BSIM3 devices of every revision now follow `.options TEMP` (b3temp.c laws) instead of being rejected, and an effective `NQSMOD=1` (or 3.3.0 `ACNQSMOD=1`) is now rejected with `UNSUPPORTED_MODEL_PARAMETER` instead of being silently simulated as the quasi-static model (#692).
- d5ee77a: B-source expressions can read voltage-source branch currents with `i(vx)`, as in ngspice-47 (#718). The value is the MNA branch current of the referenced V, E, H, L or V= B element (positive from its + node through the element), stamped with its derivative on the branch unknown for DC, AC and transient Newton and convergence tests. Inside a subcircuit `i(name)` refers to the instance's own element, and names match case-insensitively. An unknown name, or an element without a branch current, now fails with an `InvalidCircuitError` instead of the old parse rejection. The corpus-g Sandler decks SANDLER1 and SANDLER2 now run and match ngspice-47.
- 25bcf5b: `.control` scripts can now run `linearize`, `fft` and `psd` (#752), ported from ngspice-47 (linear.c, interpolate.c, com_fft.c with its FFTW path, fftext.c windows). `linearize [np=n] [vec ...]` re-interpolates the current transient plot onto the `.tran` step grid in a new `tran<n>` plot. `fft vec ...` and `psd navg vec ...` create an `sp<n>` spectrum plot with a `frequency` scale, honouring `set specwindow` / `specwindoworder`. Every length is transformed exactly without zero padding. Values match ngspice-47 to 1e-11 relative on the reference decks. examples/transient-noise/noi-sc-tr.cir now runs end to end.
- e94a7de: `.control` scripts can now run the `sp` and `sens` analysis commands (#750), with the same arguments as the `.sp` and `.sens` dot cards. Each run creates an ngspice plot, `sp<n>` or `sens<n>`. In `sp<n>`, the S/Y/Z (and noise) vectors are readable as `s_1_1`, `y_2_1`, ... (case-insensitive) over a `frequency` scale (#751). This also covers a deck `.sp` card run with `run`. `sens<n>` names its vectors like ngspice-47: `r1` (and `r1_ac` in AC), `c1`, `l1`, `v1`/`i1`, `v1_acmag`, `e1_gain`. `result.sParameters` now holds the latest S-parameter run of a control script, like every other analysis field (#751).

  `.sens` accepts `ac lin` and `ac oct` sweeps and the explicit `.sens v(node) dc` form. The sweeps follow ngspice-47 cktsens.c, including its LIN stepping, which multiplies by `(stop - start) / N`. DC sensitivity now also accepts a current source given as `dc=... ac=...`. The ngspice regression decks sens-ac-1, sens-ac-2 and sens-dc-2 pass against their golden values. sens-dc-1 still stops at `i1_m`, because multiplier and scale sensitivities are not produced yet (#760).

- d6c1197: Behavioural E/G cards (`Exxx n+ n- value={expr}` / `vol={expr}`, `Gxxx n+ n- value={expr}` / `cur={expr}`) now run as ngspice-47 ASRCs at the top level and inside subcircuits, instead of crashing `simulate()` with an uncaught `TypeError` (#789). E/G/F/H cards with missing fields or the unsupported POLY form now fail with a `ParseError` naming the card and its expected form.
- 9048f8c: MOSFET `LEVEL=3` (ngspice-47 mos3, semi-empirical short-channel model) and `LEVEL=9` (ngspice mos9) are now simulated instead of rejected with `UNSUPPORTED_MODEL_LEVEL` (#715): moseq3 drain current with NFS weak inversion, VMAX velocity saturation, THETA/ETA/KAPPA, XJ short-channel and DELTA narrow-width effects, DELVTO, LD/XL/WD/XW size adjustments, the mos3load.c cubic reverse bulk-junction tail, RD/RS (or RSH × NRD/NRS) series resistances divided by M, Meyer gate and depletion charges, the mos3conv.c device convergence test and MOS3trunc. LEVEL=9 follows mos9 exactly: a 1 µm minimum effective length/width and no `argb != 0` guard. `.noise` rejects both levels (mos3noi.c is not ported).
- 9e6b9d8: Retain every native analysis run in `SimulationResult.analyses` for multi-analysis decks, including lowered straight-line control commands. Preserve legacy last-per-type fields and per-run measurements without rerunning analyses; single-analysis, stepped and interpreted-control results are unchanged.
- fb3557e: Support uniform distributed RC lines (U cards and URC models) through ngspice-compatible geometric resistor/capacitor or diode ladder expansion. Accept explicit N/LUMPS section counts and reject unsupported parameters with structured parse errors.
- 219b04e: Independent V and I sources accept `EXP(...)`, `SFFM(...)` and `AM(...)` waveforms and the PWL `TD=` (delay) and `R=` (repeat) parameters, matching ngspice-47 vsrcload.c/isrcload.c: TSTEP/TSTOP defaults for omitted coefficients, the SFFM modulation-index clamp, the value 0 before an SFFM/AM delay, and no EXP/SFFM/AM breakpoints. A PWL with `TD=`/`R=` schedules its corners on accept like ngspice-47 vsrcacct.c, so a repeat's wrap-around jump is sampled on the same side as ngspice. New exported types `ExpSource`, `SffmSource` and `AmSource` (#716).
- 965334c: Return solver-free advisory topology warnings from spice_validate with node and element ids and repair hints. Keep simulation and default direct-core validation behavior unchanged.
- a20e83e: Support VBIC VTF forward transit-time collector-bias dependence, including AC cross-capacitance and transient charge derivatives. Preserve the disabled/default path and validate non-finite values.
- 42ab67b: XSPICE event-driven digital simulation (#553 slice 3): `d_buffer`, `d_inverter`, `d_and`, `d_nand`, `d_or`, `d_nor`, `d_xor`, `d_xnor`, `adc_bridge` and `dac_bridge` with ngspice-47 semantics (0/1/U states and strengths, rise/fall and inertial delays, `~` inverted ports, multi-driver resolution, EVTop operating point, event/analog transient coordination). Digital node values are available as `TransientResult.digital(node)`.

### Patch Changes

- c14f5ad: A bare `.param` or subcircuit parameter name as the value of an R, C or L card (`R1 in o rv`, `C1 o 0 cval`, `L1 o 0 lval`, also inside a `.subckt` with an X-line override) is now substituted like ngspice-47, which wraps such names in braces before numparam runs (inpcom.c `inp_quote_params`). It no longer fails with `references unknown model`. As in ngspice, the parameter wins over a `.model` of the same name. An unlabeled number after a resistor value (`R1 a b 3k 2k`) is now the resistance, as in ngspice-47 inp2r.c, instead of a parse error (#837).
- 33b12f4: Implement the XSPICE bidi_bridge electrical current driver and analog receiver, including tristate release, drive strengths, direction control, and automatic insertion for bidirectional mixed analog/digital nodes.
- 544bfff: `.noise` now accepts Gummel-Poon BJTs whose model sets junction capacitances (CJE/VJE/MJE, CJC/VJC/MJC, XCJC, FC), transit times (TF/XTF/VTF/ITF, TR), VAR, IKR, ISC/NC, NKF or the XTI/XTB/EG temperature inputs (and their ngspice aliases). These only change the operating point and the bjtacld.c small-signal transfer, which the DC solve and AC stamp already model, not the bjtnoise.c sources. Onoise/inoise match ngspice-47 within 1.5e-6 on a CJE/CJC/TF/TR/VAF/VAR deck, and the corpus-g decks MULTIPLICITY_FACTOR/bjt_diffpair_noise_baseline.net and NOISE/cascodeBjtNOISE.cir now run. RBM/IRB, the substrate diode (ISS) and TNOM are still rejected (#736).
- 51be0bf: BJT fixes for ngspice-47 parity (#767):
  - On an `NPN`/`PNP` card that selects the level-1/2 BJT, a name that ngspice-47 has in neither its BJT model table nor its BJT instance table (for example the MEXTRAM `DTA`, `VEF` or `TAUB` on a `LEVEL=504` card) is now ignored with ngspice's `unrecognized parameter (dta) - ignored` parse warning. It no longer fails with `Unsupported bounded BJT model parameter`. Names that ngspice-47 implements and spice-ts does not (for example `RCO`, `IBE`, or `AREA` on the model card) are still rejected.
  - AC, noise and pole-zero no longer stamp the BJT substrate diode conductance, since ngspice-47 bjtacld.c/bjtpzld.c do not. The substrate terminal sees only the substrate capacitance there, while the operating point keeps the diode.
  - `.noise` input-referred noise divides by max(|gain|², 1e-20), as ngspice-47 noisean.c (N_MINGAIN) does.
  - `.noise` accepts BJT `TNOM`/`TREF` and the substrate parameters `ISS`, `NS`, `CJS`, `VJS`, `MJS` and `SUBS`.
- 3a09e25: Gummel-Poon BJTs with `XCJC < 1` together with `RB > 0` now simulate instead of failing with `Unsupported BJT model parameter: 'XCJC' < 1 together with RB > 0`. Like ngspice-47 bjtload.c and bjtacld.c, the `(1 - XCJC)*CJC` part of the base-collector depletion capacitance sits between the external base and the internal collector, outside RB, in `.op`, `.ac` and `.tran`. BJTtrunc leaves it out of the timestep control, and spice-ts now does the same. A self-written two-stage deck matches ngspice-47 `-b` to 1e-9 (op) and 1e-7 (ac), and its transient to 1.3 mV. The TI OPA690 macromodel bench from ngspice-bugs #737 gives op v(out) = -0.18920212436 and |v(out)| = 1.99794712955 at 1 kHz, as in ngspice-47. `.noise` rejects such a BJT rather than drop its RB thermal noise (#861).
- 7f07549: BJT `VAF`, `IKF`, `VAR` and `IKR` given as `0` now mean infinite (no Early effect / no high-injection roll-off), as in ngspice-47 bjttemp.c, instead of failing with `Invalid bounded BJT model parameter value` (#844). Vendor cards such as Fairchild's `PN2222.mod` (`Isc=0 Ikr=0`) now simulate and match ngspice-47. Negative values are still rejected.
- 8dd2691: BSIM3 (LEVEL=8/49, VERSION 3.3): replace the Meyer-style capacitance approximation with a port of the ngspice-47 b3ld.c charge model (capMod 0-3, XPART partitions, bias-dependent overlap, junction charge with temperature laws), integrated as terminal charges with the full nonreciprocal Jacobian. Fixes the adder_mos_circ supply current (#626) and the 6T SRAM write (#582).
- 1426fc1: BSIM3 (LEVEL=8/49, every VERSION): model the `RSH × NRD` / `RSH × NRS` drain and source series resistances like ngspice-47 b3set.c/b3v32set.c, with `NRD = NRS = 1` square by default, prime nodes only for non-zero values and `M` dividing the resistance (#691). Before, they were silently dropped (a 9.7% drain-current error on the corpus-f TSMC 0.25u card). A card with `ACM` other than 0 is now rejected with `UNSUPPORTED_MODEL_PARAMETER` instead of being simulated as ACM = 0.
- dd4e58b: BSIM3 VERSION=3.2 / 3.2.2: reproduce the ngspice-47 b3v32temp.c size-record (`pParam`) reuse (#700). An instance whose L/W repeats a geometry of its model now takes vth0/vfb/vfbzb/u0temp from the last newly-seen geometry in ngspice's (reverse netlist) instance order, as ngspice does; before, spice-ts used the instance's own record, up to 14% drain-current difference on alternating geometries of the corpus-f TSMC 0.25u card. 3.2.3, 3.2.4 and 3.3.0 are unchanged.
- 283e0c7: A B-source `V(x)^-0.5` (or any `^`/`**`/`pow()` that is +inf at a zero base) no longer aborts with "0, -0.5 out of range for ^" on Newton's all-zero first iterate. ngspice-47 only reports an expression range error for its HUGE sentinel, which `<math.h>` defines as FLT_MAX, not for an IEEE +inf, so +inf is now an ordinary value: the solve propagates it like ngspice's sparse solver and Newton moves on (`V1 in 0 0.25` / `B2 n2 0 V = V(in)^-0.5` gives v(n2) = 2, V1 = 0 gives inf, V1 = -1 gives 0, as ngspice-47). Overflows such as `10^400` evaluate to inf instead of a range error; sqrt/log of a negative still raise one. A signed or computed exponent such as `-0.5` or `(1/2)` now takes ngspice's general power-derivative rule, because ngspice's parser does not fold it into a constant (reverting that part of #886). Fixes #891.
- 2fe281d: Allow a finite-Jacobian B-source solve overflow when the expression itself evaluates to signed infinity at finite control values, matching ngspice-47 operating-point output for `V(in)*1e307`. Preserve singular-matrix and uncertified finite-overflow guards. On this certified nonfinite path only, retain the converging linearisation point rather than the subsequent `inf - inf` NaN solve. Fixes #899.
- a198748: A B-source `pow(x, c)`, `x^c` or `x**c` with an exponent below 1 no longer fails with a singular matrix when `x` is 0 on a Newton iterate (every node starts at 0, so `pow(V(in), 0.5)` and PSpice `pwrs(V(in), 0.5)` failed for any input). The slope c*pwr(x, c-1) now moves a zero base to ngspice-47's PTfudge_factor (gmin*1e-20), the guard ngspice PTpwr applies in PSpice mode, so the Jacobian stays finite. A folded constant exponent such as `-0.5` or `(1/2)` now takes ngspice's literal-exponent derivative rule, as ngspice's parser folds it to one constant. Where default-mode ngspice-47 aborts (input held at exactly 0), spice-ts converges to the 0 that ngspice-47 PSpice mode returns (#886).
- a2001a9: B-source expressions accept the PSpice functions `IF(c, a, b)`, `LIMIT(x, a, b)`, `PWRS(x, a)`, `STP(x)` and `INT(x)` that ngspice-47 defines in PSpice compatibility mode (frontend/inpcompat.c `.func` set), as used by vendor op-amp libraries (`bE1 ... IF(...)` in AD620, `bG1 ... LIMIT(...)` in OPA818). Each expands into the same `ternary_fcn`/`min`/`max`/`sgn`/`pow`/`u`/`floor` tree as in ngspice-47, so values and Newton derivatives match `ngbehavior=psa`; `LIMIT` takes its bounds in either order. `pwr` keeps the native ngspice meaning (#879).
- a298c8f: Fold node and element names case-insensitively, as ngspice does: `F` and `f` are now one node (also inside `.subckt` expansion and B-source `v()` references), K cards couple `l1`/`L2`, and F/H/W/`i()` control-source lookups ignore case. - 34cac39: Faster transient step control on decks with many linear capacitors or inductors: the CAPtrunc/INDtrunc truncation check now evaluates all charges into one reused buffer and bounds them in a single loop, with no per-charge closure, dispatch or array allocation. - e2c73b2: Transient step control follows ngspice-47 CKTtrunc: CAPtrunc, INDtrunc and DIOtrunc bound the step on device charges, and the node-voltage LTE only remains on nodes of devices without a DEVtrunc port (#621). Fixes the CJSW diode transient that stopped with TimestepTooSmallError (#646).
- f7a24b4: `Circuit.compile()` folds each distinct node spelling once instead of once per terminal, resolves names that are already the display spelling directly, skips the `.global` lookup when there are no globals, and builds resistors without a model card without the model-default merge. Compile time on the #426 M2 scaling decks is 1.2-1.7x lower (resistor mesh 1.5-1.7x, RC ladder 1.2-1.4x, MOS1 inverter chain 1.1-1.2x); node indices and results are unchanged (#796).
- 3a5f929: The complex AC LU (AC, noise, distortion) now orders columns with the same fill-reducing AMD ordering as the real sparse LU, computed once per topology on the union pattern of G and C, with structural column singletons first and the permuted diagonal as preferred pivot (#740).

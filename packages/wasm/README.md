# @spice-ts/wasm

Protocol-v1 module-worker facade with explicit TypeScript and bounded numeric WebAssembly backends.

```ts
import { createSpiceEngine } from '@spice-ts/wasm';

const engine = await createSpiceEngine({ backend: 'spice-ts-wasm' });
const response = await engine.simulate({
  apiVersion: '1',
  input: { format: 'spice', source: 'V1 in 0 AC 1\nR1 in out 1k\nC1 out 0 1u\n.ac dec 3 10 10k' },
}, { requestId: 'ac-1' });
await engine.close();
```

## Backends

`spice-ts-js` runs the existing TypeScript engine. It supports the facade's established OP, DC, transient and AC protocol slice.

`spice-ts-wasm` runs real and split-complex WebAssembly dense f64 Gaussian-elimination kernels for four deliberately narrow subsets:

- SPICE text input only
- exactly one unstepped analysis
- `.op` with resistors, independent constant/DC voltage and current sources, linear VCCS, CCCS, VCVS, and CCVS controlled sources, and bounded diode/BJT/MOS1 models (`R`, `V`, `I`, `G`, `F`, `E`, `H`, `D`, `Q`, `M`)
- `.dc` with one linear sweep of one independent constant/DC voltage or current source, resistors, linear E/F/G/H controlled sources and bounded diodes/BJTs/MOS1 (`R`, `V`, `I`, `E`, `F`, `G`, `H`, `D`, `Q`, `M`)
- `.tran` with resistors, capacitors, four-token constant-value linear inductors, linear E/F/G/H controlled sources, and independent constant/DC, `PULSE`, `SIN(VO VA FREQ TD THETA PHASE)`, or `PWL(t1 v1 ...)` voltage and current sources (`R`, `C`, `L`, `E`, `F`, `G`, `H`, `V`, `I`); each inductor adds one branch unknown and starts from its DC short-circuit operating point
- `.ac lin|dec|oct` with positive finite resistors, capacitors and inductors plus independent voltage/current sources, linear E/F/G/H controlled sources and bounded diodes/BJTs/MOS1 (`R`, `C`, `L`, `V`, `I`, `E`, `F`, `G`, `H`, `D`, `Q`, `M`)
- AC sources may use constant, `DC`, `AC magnitude [phase]`, or `DC value AC magnitude [phase]` forms
- at most 65,536 source bytes, 256 components and 64 numeric unknowns
- at most 1,025 AC frequency points, further reduced by the caller's `maxResultPoints`
- passive constant/DC/PULSE transients use at most 4,096 fixed-step trapezoidal points; SIN/PWL and diode/BJT/MOS1 transients use an adaptive point budget (see below), both further reduced by the caller's `maxResultPoints`
- at most 4,096 DC-sweep points, further reduced by the caller's `maxResultPoints`
- fixed three-page WebAssembly memory with no imports or growth

The WebAssembly backend does not support native/circuit-json input, virtual files, includes, subcircuits, models other than the bounded diode/BJT/MOS1 models below, parameters, controlled sources other than six-token linear `G`, five-token linear `F`, six-token linear `E`, and five-token linear `H` forms in OP/DC/TRAN/AC, nonlinear devices other than bounded OP/DC-sweep diodes/BJTs/MOS1, switches, `.step`, nested/stepped DC sweeps, nonlinear DC source forms, transient UIC/initial conditions, start/max-time controls, caller-specified LTE controls, or non-trapezoidal integration. Controlled-source gains must be constant numeric values; POLY, VALUE, TABLE and expression-valued forms return structured `UNSUPPORTED_FEATURE` validation errors. CCCS and CCVS controlling sources must resolve to a preceding independent voltage-source branch; missing, branchless and forward references return a structured `INVALID_CIRCUIT` validation error. Each VCVS or CCVS contributes one branch unknown to the 64-unknown ceiling. Coupled inductors (`K`) return `UNSUPPORTED_FEATURE` with feature `inductor-coupling`, inductor `IC=` returns `inductor-initial-condition`, and inductor models, instance parameters, and expression or nonlinear values return `inductor-form`. AC and compound transient source forms remain unsupported. Unsupported input returns `UNSUPPORTED_FEATURE`; invalid grids return `INVALID_CIRCUIT`; exceeded bounds return `RESOURCE_LIMIT`. There is no automatic fallback. A caller that wants the TypeScript path must select `spice-ts-js` explicitly.

The dense kernels are intentionally bounded and are not a speed claim. AC has O(points × n³) runtime and O(n²) memory, and transferring the verified 4,418-byte artifact with each one-shot worker request adds overhead. Sparse WASM remains unsupported.

Diode operating points, DC sweeps and transients accept four-token `Dname anode cathode model` instances and `.model name D(IS=... N=... RS=...)` (all three parameters optional). Newton iteration reuses core's diode companion model, ngspice-style junction limiting and convergence tolerances around the WASM linear solve, with no TypeScript solver fallback. DC sweeps warm-start Newton from the previous point. The OP/DC per-point iteration budget defaults to 100, capped at 1,000; exhausted budgets return `CONVERGENCE_FAILED`. Other diode model parameters (including BV and CJO outside AC) and instance parameters return `UNSUPPORTED_FEATURE`. The diode fixtures are original project-authored circuits under this repository's MIT licence, not imported benchmark material.

Diode AC additionally accepts `CJO` (alias `CJ0`), `VJ`, `M`, `FC`, and `TT`. It computes the DC bias using the WASM Newton solve, then stamps junction conductance, depletion capacitance and diffusion capacitance at that operating point. Core expands `RS` into a physical resistor/internal junction node; the split-complex WASM kernel solves every frequency without a JS solver fallback. BJT/MOS AC and other diode parameters remain unsupported with structured errors. All source, component, unknown and frequency-point ceilings above are unchanged. Reproduce the original MIT diode+RC identical-deck ngspice comparison with `pnpm -C packages/wasm build && pnpm -C packages/wasm exec tsx scripts/diode-ac-accuracy.ts`; the runner prints hashes, version, machine, matched-point max/RMS errors and both engines' losses, without a speed claim.

SIN/PWL and diode/BJT/MOS1 transient exception to the fixed-step limitations above: adaptive timesteps use core's transient driver, including WASM-backed DC initialization. SIN damping/phase and PWL repeated-time corners use core's waveform evaluation and existing breakpoint semantics. PWL corners are scheduled on accepted steps; SIN TD is not currently an explicit breakpoint in either backend. Every linear solve uses the dense WASM kernel, not the JS solver. Set `createSpiceEngine({ backend: 'spice-ts-wasm', maxPoints: 12000 })` to change the adaptive accepted-point budget. The default is 4096, including t=0; positive safe integers only. Exceeding it returns a typed protocol `RESOURCE_LIMIT` error with `details: { limit: 'maxPoints', configured, observed }`. `options.limits.maxResultPoints` remains an independent, potentially smaller limit. Constant/DC/PULSE passive transient, OP/DC and AC bounds are unchanged. Transient Newton budgets and rejection/recovery follow the shared core driver. Original MIT fixtures in `src/numeric-wasm-sources-tran.test.ts` compare SIN-driven RC and repeated-corner PWL-driven RC/RLC circuits for voltage and current sources against core at identical accepted point counts and unchanged absolute bounds of 1e-9 V and 1e-12 A. These checks do not establish ngspice parity or a speed advantage.

Known limitation (#1606, residual strict parity in #1571): the rectifier in `src/numeric-wasm-diode-tran.test.ts` has identical 2008-point grids at default options and measured maximum absolute signal delta `1.2212453270876722e-15` against core (test bound `1e-12`). With unchanged `reltol=1e-10`, `vntol=1e-13`, `abstol=1e-16`, both paths finish at 10215 points with `maxPoints: 12000`, but dense/sparse rounding feeds adaptive LTE decisions. Measured index-wise maximum signal delta is `8.979594845470729e-10` (expected-difference bound `9e-10`, explicitly greater than `1e-10`) and maximum time delta is `1.0431846358960328e-13` s (bound `1.1e-13`). This is not strict tight-tolerance parity.

Reproduce the original MIT rectifier comparison on identical netlist bytes with `spice-heavy pnpm exec tsx packages/wasm/scripts/diode-tran-accuracy.ts` (ngspice-47 required). On arm64 Apple M5 Pro, all node voltages and source currents compared to ngspice interpolated onto WASM times gave default-options max/RMS absolute error `5.8778753319055355e-5 / 5.518338202772876e-6` before versus `5.564847601946532e-6 / 2.715901086240641e-7` after. The tight-options comparison against the same default-options ngspice run is a loss: `5.8778752727972616e-5 / 5.518483580695964e-6` before versus `8.164889731205292e-5 / 1.2181421220621299e-5` after. Before had 2001 points; after has 2008/default or 10215/tight. No speed or tight-ngspice-parity claim is made.

BJT operating points, DC sweeps, transients and AC accept five-token `Qname collector base emitter model` instances and `.model name NPN(...)` or `PNP(...)`, with optional `IS`, `BF`, `BR`, `NF`, `NR`, `VAF`, `RC`, and `RE` only. Constant collector/emitter series resistances use core's physical resistor/internal-node expansion in every analysis. This Gummel-Poon DC subset reuses core's companion model and junction-based Newton step limiter around the WASM linear solve with the same bounded per-point iteration budget in OP/DC. DC sweeps retain device state and warm-start Newton from the previous solution. Transients use the shared adaptive driver above with this same static BJT subset and external capacitors/inductors; intrinsic charge is not yet supported. AC computes the WASM operating point, stamps core's small-signal conductances there, and solves each frequency with the WASM complex kernel; only external capacitors/inductors provide frequency dependence. Charge, temperature, base resistance, other model parameters (including CJE, TF, RB, IRB, RBM and XTI), and substrate/area/instance options are rejected with `UNSUPPORTED_FEATURE`; unsupported model parameters identify feature `bjt-model-parameter`. Other nonlinear devices remain unsupported. The original MIT fixtures in `src/numeric-wasm-bjt.test.ts` compare NPN/PNP forward-active, saturation, cutoff and reverse-active resistor bias networks against core at a uniform 1e-9 relative plus 1e-12 absolute tolerance. `src/numeric-wasm-bjt-dc.test.ts` compares every node voltage and source branch current in mirrored common-emitter VBE/VCE sweeps, in both directions, at 1e-9 relative or 1e-12 absolute tolerance. `src/numeric-wasm-bjt-ac.test.ts` compares every node-voltage and source-current magnitude/phase for mirrored common-emitter, common-base and forward-biased collector-base junction stages over 10 Hz–100 kHz at the unchanged diode-AC relative bound of 1e-9. `src/numeric-wasm-bjt-series.test.ts` compares every node voltage and source current for mirrored RC-only, RE-only and combined RC=10/RE=2 decks in all four analyses at those same tolerances (AC magnitude/phase: 1e-9 relative). These are bounded backend correctness checks, not speed or general ngspice-parity claims. Reproduce oracle comparisons (including losses) with `spice-heavy pnpm -C packages/wasm exec tsx scripts/bjt-ac-accuracy.ts` after building.

The original MIT PULSE-driven common-emitter fixtures with external collector capacitance in `src/numeric-wasm-bjt-tran.test.ts` were rejected before #1614. Afterward both NPN and PNP match core's exact 188-point default-options time grid, with maximum node-voltage deltas `1.27675647831893e-14` and `1.3988810110276972e-14` V (uniform test bound `1e-9` V absolute). Maximum source-current deltas are `1.1600963245594897e-17` and `7.101524229780054e-18` A (bound `1e-12` A). The tests also check deterministic repetition, exact and exceeded point budgets, and rejection of out-of-subset parameters. No tight-tolerance parity or speed claim is made.

MOS1 operating points and DC sweeps accept six-token `Mname drain gate source bulk model` instances with optional numeric `W` and `L`. Models are `.model name NMOS(...)` or `PMOS(...)`, with optional `LEVEL=1`, `VTO`, `KP`, `LAMBDA`, `GAMMA` and `PHI`; omitted parameters use core's ngspice-compatible defaults. Newton reuses core's MOS1 companion equations, body-junction limiting and convergence checks around the existing WASM linear solve, with the same bounded per-point iteration budget and no fallback. DC sweeps retain device state and warm-start Newton from the previous solution. Other levels/model parameters (including RD and temperature) and unsupported instance options return structured `UNSUPPORTED_FEATURE` (`mosfet-model-parameter` or `mosfet-form`). The numeric kernel/artifact is unchanged.

MOS1 AC additionally accepts instance `AD`, `AS`, `PD`, `PS` and model `TOX`, `CGSO`, `CGDO`, `CGBO`, `CBD`, `CBS`, `CJ`, `CJSW`, `PB`, `MJ`, `MJSW`, `FC`, matching the transient charge subset. It linearizes core's gm/gds/gmbs, Meyer, overlap and junction capacitances at the WASM operating point, then uses the WASM complex solver. Mirrored common-source, body-driven, triode and inverse-mode tests compare `v(out)` magnitude and phase over 91 points from 1 Hz to 1 GHz with the BJT AC test's unchanged `1e-9` relative bound. Reproduce oracle comparisons with `spice-heavy pnpm -C packages/wasm exec tsx scripts/mos1-ac-accuracy.ts` after building. This is output-voltage parity, not a claim of `1e-9` relative agreement for every source current or near-zero signal; the runner reports those losses too. No speed claim is made.

MOS1 transients use the shared adaptive driver and explicit `maxPoints` budget described above for diodes/BJTs. Transients additionally accept numeric instance `AD`, `AS`, `PD`, `PS` and model `TOX`, `CGSO`, `CGDO`, `CGBO`, `CBD`, `CBS`, `CJ`, `CJSW`, `PB`, `MJ`, `MJSW`, `FC`. These enable core's Meyer gate charge and bottom/sidewall junction charge, not other MOS levels. OP/DC parameter subsets are unchanged.

The original MIT CMOS inverter in `benchmarks/wasm-mos1-tran/inverter.cir` was rejected before this extension. Default-options WASM/core both produce 230 accepted points; maximum node-voltage difference is `2.461586490198897e-12` V (unchanged BJT absolute bound `1e-9` V), and source-current difference is `2.813098061785202e-16` A (bound `1e-12` A). Tests assert identical accepted point counts and the ordered accept/reject sequence (229 advanced accepts plus t=0, 16 rejected trials). Dense/sparse rounding feeds LTE: accepted times differ by up to `1.641126335305207e-21` s, within the supervisor-approved `1e-12 * tstop` bound asserted for every point, not bit equality. ### Measured cost of this slice

Measured on 2026-10-10 with Node 22.23.1, pnpm 10.28.1, ngspice-47, LLVM/LLD 23.1.3 and an arm64 Apple M5 Pro. The fixed five-circuit AC suite uses byte-identical netlists for both spice-ts backends and ngspice. Its 29 WASM frequency points produced these aggregate rectangular-complex errors:

| Reference | Compared samples | Max absolute | RMS absolute | Max relative | RMS relative |
| --- | ---: | ---: | ---: | ---: | ---: |
| `spice-ts-js` | 64 | 4.4492e-16 | 1.5426e-16 | 1.7826e-15 | 2.9435e-16 |
| ngspice-47 | 63 | 1.1571e-15 | 2.1615e-16 | 1.3279e-15 | 3.7118e-16 |

The identical-netlist LIN regressions match ngspice-47 exactly: N=1 yields `[100]` Hz and N=4 yields `[100, 400, 700, 1000]` Hz. One ngspice endpoint was excluded because its floating frequency landed just below spice-ts's final OCT point; the complete per-fixture grids and every signal metric are retained in `ac-accuracy-results.json`. No zero-reference samples were excluded.

Five samples each ran 20 one-shot worker simulations after five warmups. Median time was 1,490.678 ms for `spice-ts-js` (74.5339 ms/run) and 1,492.458 ms for `spice-ts-wasm` (74.6229 ms/run), a 0.1194% WASM loss. This worker-dominated difference is noise-level and is not a speed claim. The measured size losses are larger: the artifact grows from 1,190 to 2,900 bytes (+143.70%), worker.js from 355,517 to 377,009 bytes (+6.05%), index.js from 41,878 to 42,815 bytes (+2.24%), and their combined uncompressed size grows 24,139 bytes (+6.06%). Larger or sparse circuits cannot use this backend at all.

## Integrity and isolation

`createSpiceEngine` verifies `dist/worker.js` and, for `spice-ts-wasm`, `dist/dense-solver.wasm` against `dist/manifest.json` before constructing a worker. Missing, malformed or mismatched assets fail with `BACKEND_UNAVAILABLE`. Build IDs use the first 16 hexadecimal characters of the selected artifact's SHA-256.

The checked-in numeric artifact is copied during package builds, not rebuilt using an ambient toolchain. Its reviewable C source, pinned regeneration command, expected hash, size and ABI v2 are documented in `native/README.md`. ABI v2 exposes bounded linear VCCS, CCCS, VCVS, and CCVS stamps plus the real and split-complex solver entry points.

The worker receives request values and the already verified numeric bytes only. It exposes no WASI, socket, host-filesystem, clock, randomness or ambient fallback API. Package build and test scripts do not publish or deploy anything.

## Streaming and cancellation

`simulateStream` emits fixed point-count chunks after the one-shot worker returns. OP has no point events. AC arrays are bounded to 1,025 points and DC/transient arrays to 4,096 points before allocation. `cancel(requestId)` terminates the operation's one-shot worker; cancellation before asynchronous worker construction is also registered. Caller wall-time expiry terminates the worker. The fixed 64-unknown ceiling bounds each non-interruptible solve.

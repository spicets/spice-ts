# @spice-ts/wasm

Protocol-v1 module-worker facade with explicit TypeScript and bounded numeric WebAssembly backends.

```ts
import { createSpiceEngine } from '@spice-ts/wasm';

const engine = await createSpiceEngine({ backend: 'spice-ts-wasm' });
const response = await engine.simulate({
  apiVersion: '1',
  input: { format: 'spice', source: 'V1 in 0 AC 1\nR1 in out 1k\nC1 out 0 1u\n.ac dec 3 10 10k' },
}, { requestId: 'ac-1' });
await engine.close();
```

## Backends

`spice-ts-js` runs the existing TypeScript engine. It supports the facade's established OP, DC, transient and AC protocol slice.

`spice-ts-wasm` runs real and split-complex WebAssembly dense f64 Gaussian-elimination kernels for four deliberately narrow subsets:

- SPICE text input only
- exactly one unstepped analysis
- `.op` with resistors, constant inductors and K coupling, independent constant/DC voltage and current sources, linear VCCS, CCCS, VCVS, and CCVS controlled sources, and bounded diode/BJT/MOS1/JFET models (`R`, `L`, `K`, `V`, `I`, `G`, `F`, `E`, `H`, `D`, `Q`, `M`, `J`)
- `.dc` with one or two nested linear sweeps of independent constant/DC voltage or current sources (first source varies fastest), resistors, constant inductors and K coupling, linear E/F/G/H controlled sources and bounded diodes/BJTs/MOS1/JFETs (`R`, `L`, `K`, `V`, `I`, `E`, `F`, `G`, `H`, `D`, `Q`, `M`, `J`)
- `.tran` with resistors, capacitors, four-token constant-value linear inductors and K coupling, linear E/F/G/H controlled sources, and independent constant/DC, `PULSE`, `SIN(VO VA FREQ TD THETA PHASE)`, or `PWL(t1 v1 ...)` voltage and current sources (`R`, `C`, `L`, `K`, `E`, `F`, `G`, `H`, `V`, `I`); each inductor adds one branch unknown and starts from its DC short-circuit operating point
- `.ac lin|dec|oct` with positive finite resistors, capacitors and inductors, constant K coupling, independent voltage/current sources, linear E/F/G/H controlled sources and bounded diodes/BJTs/MOS1/JFETs (`R`, `C`, `L`, `K`, `V`, `I`, `E`, `F`, `G`, `H`, `D`, `Q`, `M`, `J`)
- AC sources may use constant, `DC`, `AC magnitude [phase]`, or `DC value AC magnitude [phase]` forms
- at most 65,536 source bytes, 256 components and 64 numeric unknowns
- at most 1,025 AC frequency points, further reduced by the caller's `maxResultPoints`
- passive uncoupled constant/DC/PULSE transients use at most 4,096 fixed-step trapezoidal points; coupled-inductor, SIN/PWL and diode/BJT/MOS1/JFET transients use an adaptive point budget (see below), both further reduced by the caller's `maxResultPoints`
- at most 4,096 DC-sweep points, further reduced by the caller's `maxResultPoints`
- fixed three-page WebAssembly memory with no imports or growth

The WebAssembly backend does not support native/circuit-json input, virtual files, includes, subcircuit-local `.param` cards, models other than the bounded diode/BJT/MOS1/JFET models below, controlled sources other than six-token linear `G`, five-token linear `F`, six-token linear `E`, and five-token linear `H` forms in OP/DC/TRAN/AC, nonlinear devices other than bounded OP/DC-sweep diodes/BJTs/MOS1/JFETs, switches, `.step`, DC sweeps with three or more sources or non-source outer dimensions (including TEMP), stepped DC sweeps, nonlinear DC source forms, transient UIC/initial conditions, start/max-time controls, caller-specified LTE controls, or non-trapezoidal integration. Controlled-source gains must be constant numeric values; POLY, VALUE, TABLE and expression-valued forms return structured `UNSUPPORTED_FEATURE` validation errors. CCCS and CCVS controlling sources must resolve to a preceding independent voltage-source branch; missing, branchless and forward references return a structured `INVALID_CIRCUIT` validation error. Each VCVS or CCVS contributes one branch unknown to the 64-unknown ceiling. Constant coupled inductors (`Kname Lx Ly k`, |k| <= 1) are supported in OP/DC/TRAN/AC using core mutual-inductance stamps. References must identify two distinct, previously declared inductors (case-insensitive); missing, duplicate, non-inductor or forward references and out-of-range k return structured `INVALID_CIRCUIT` errors. Expression-valued k returns `UNSUPPORTED_FEATURE` with feature `inductor-coupling`. Each inductor contributes one branch unknown to the 64-unknown ceiling; K adds none. Inductor `IC=` returns `inductor-initial-condition`, and inductor models, instance parameters, and expression or nonlinear values return `inductor-form`. AC and compound transient source forms remain unsupported. Unsupported input returns `UNSUPPORTED_FEATURE`; invalid grids return `INVALID_CIRCUIT`; exceeded bounds return `RESOURCE_LIMIT`. There is no automatic fallback. A caller that wants the TypeScript path must select `spice-ts-js` explicitly.

`.subckt` definitions and `X` instances support OP/DC/TRAN/AC, including nested definitions, case-insensitive lookup and local models. Definitions accept `PARAMS: name=value` defaults and instances accept `name=value` overrides, using numeric literals or braced expressions over subcircuit parameters and top-level `.param` values. Core supplies parameter evaluation, expansion and hierarchical names; all numeric solves remain in WASM. Existing device restrictions apply within definitions and the 64-unknown limit applies after expansion. Hierarchical transients share core's adaptive driver and accepted time grids. Subcircuit-local `.param` cards return `UNSUPPORTED_FEATURE` with `details.feature = "subcircuit-parameters"`. Undefined subcircuits, wrong port counts and recursion return `INVALID_CIRCUIT`. The original MIT fixtures in `src/numeric-wasm-subckt-params.test.ts` compare all exported numeric values against core on identical netlists and grids, at 1e-12 relative for OP and 1e-9 for DC/TRAN/AC (absolute at zero). This is backend parity evidence, not an ngspice or speed claim.

Resistors and diodes accept circuit `.temp`, `.options TEMP=` and `.options TNOM=` in OP/DC/TRAN/AC. Resistors use instance/model `TC1`, `TC2` and `TNOM`; diode models with circuit temperature cards also accept `EG`, `XTI`, `TNOM` and `TBV1`. Core supplies temperature-scaled device stamps, including diode IS/VJ/CJO, while solves remain in WASM. JFET circuit temperature stays OP/DC-only (`circuit-temperature`); MOS1 also supports AC/TRAN as described below. Original MIT fixtures in `src/numeric-wasm-temperature-dynamic.test.ts` cover a half-wave rectifier and diode-biased RC at 75 C and -20 C. AC pointwise magnitude/phase relative error is below `1e-9`; transient voltages and currents satisfy `|wasm - core| <= max(1e-12, 1e-9 * |core|)` at every sample with identical time grids, using the uniform WASM parity contract. Strict transient pointwise relative error is **not** below `1e-9`: raw maxima are `1.2418058669615883e-7` at 75 C and `1.7549607339874e-7` at -20 C near zero source currents. Maximum absolute errors are `1.865174681370263e-14` and `1.6209256159527285e-14`, respectively. The test prints raw pointwise relative and absolute maxima without peak normalization. These are core-backend parity results, not ngspice or speed claims.

The dense kernels are intentionally bounded and are not a speed claim. AC has O(points × n³) runtime and O(n²) memory, and transferring the verified 4,418-byte artifact with each one-shot worker request adds overhead. Sparse WASM remains unsupported.

Diode operating points, DC sweeps, AC and transients accept four-token `Dname anode cathode model` instances and optional model parameters `IS`, `N`, `RS`, `CJO` (alias `CJ0`), `VJ`, `M`, `FC`, `TT`, `BV`, and `IBV`. Newton iteration reuses core's diode companion model, ngspice-style junction limiting and convergence tolerances around the WASM linear solve, with no TypeScript solver fallback. DC sweeps warm-start Newton from the previous point. The OP/DC per-point iteration budget defaults to 100, capped at 1,000; exhausted budgets return `CONVERGENCE_FAILED`. Other diode model parameters and instance parameters return `UNSUPPORTED_FEATURE`. Unsupported model parameters identify the uppercase parameter in `details.feature`, for example `diode-model-parameter:CJSW`. The diode fixtures are original project-authored circuits under this repository's MIT licence, not imported benchmark material. Reproduce charge/breakdown parity against core with `pnpm -C packages/wasm build && pnpm -C packages/wasm exec vitest run src/numeric-wasm-diode-params.test.ts`.

Diode AC computes the DC bias using the WASM Newton solve, then stamps junction conductance, depletion capacitance and diffusion capacitance at that operating point. Core expands `RS` into a physical resistor/internal junction node; the split-complex WASM kernel solves every frequency without a JS solver fallback. BJT/MOS AC and other diode parameters remain unsupported with structured errors. All source, component, unknown and frequency-point ceilings above are unchanged. Reproduce the original MIT diode+RC identical-deck ngspice comparison with `pnpm -C packages/wasm build && pnpm -C packages/wasm exec tsx scripts/diode-ac-accuracy.ts`; the runner prints hashes, version, machine, matched-point max/RMS errors and both engines' losses, without a speed claim.

Coupled-inductor, SIN/PWL and diode/BJT/MOS1 transient exception to the fixed-step limitations above: adaptive timesteps use core's transient driver, including WASM-backed DC initialization. SIN damping/phase and PWL repeated-time corners use core's waveform evaluation and existing breakpoint semantics. PWL corners are scheduled on accepted steps; SIN TD is not currently an explicit breakpoint in either backend. Every linear solve uses the dense WASM kernel, not the JS solver. Set `createSpiceEngine({ backend: 'spice-ts-wasm', maxPoints: 12000 })` to change the adaptive accepted-point budget. The default is 4096, including t=0; positive safe integers only. Exceeding it returns a typed protocol `RESOURCE_LIMIT` error with `details: { limit: 'maxPoints', configured, observed }`. `options.limits.maxResultPoints` remains an independent, potentially smaller limit. Constant/DC/PULSE passive transient, OP/DC and AC bounds are unchanged. Transient Newton budgets and rejection/recovery follow the shared core driver. Original MIT fixtures in `src/numeric-wasm-sources-tran.test.ts` compare SIN-driven RC and repeated-corner PWL-driven RC/RLC circuits for voltage and current sources against core at identical accepted point counts and unchanged absolute bounds of 1e-9 V and 1e-12 A. These checks do not establish ngspice parity or a speed advantage.

Known limitation (#1606, residual strict parity in #1571): the rectifier in `src/numeric-wasm-diode-tran.test.ts` has identical 2008-point grids at default options and measured maximum absolute signal delta `1.2212453270876722e-15` against core (test bound `1e-12`). With unchanged `reltol=1e-10`, `vntol=1e-13`, `abstol=1e-16`, both paths finish at 10215 points with `maxPoints: 12000`, but dense/sparse rounding feeds adaptive LTE decisions. Measured index-wise maximum signal delta is `8.979594845470729e-10` (expected-difference bound `9e-10`, explicitly greater than `1e-10`) and maximum time delta is `1.0431846358960328e-13` s (bound `1.1e-13`). This is not strict tight-tolerance parity.

BJT operating points, DC sweeps, transients and AC accept five-token `Qname collector base emitter model` instances and `.model name NPN(...)` or `PNP(...)`, with optional `IS`, `BF`, `BR`, `NF`, `NR`, `VAF`, `RB`, `RC`, `RE`, `CJE`, `VJE`, `MJE`, `CJC`, `VJC`, `MJC`, `FC`, `TF`, and `TR`. Constant base/collector/emitter series resistances use core's physical resistor/internal-node expansion in every analysis. This Gummel-Poon DC subset reuses core's companion model and junction-based Newton step limiter around the WASM linear solve with the same bounded per-point iteration budget in OP/DC. DC sweeps retain device state and warm-start Newton from the previous solution. Transients integrate core's depletion and diffusion charges with accepted/rejected-step history through the shared adaptive driver above. AC computes the WASM operating point, stamps core's small-signal conductances and charge Jacobian there, and solves each frequency with the WASM complex kernel. Charge parameters have no effect on OP/DC. Current-dependent base resistance (IRB/RBM), extended charge parameters (including XTF, VTF, ITF, PTF and CJS), other model parameters, and substrate/area/instance options are rejected with `UNSUPPORTED_FEATURE`; unsupported model parameters identify feature `bjt-model-parameter`. Other nonlinear devices remain unsupported. These are bounded backend correctness checks, not speed or general ngspice-parity claims. Reproduce oracle comparisons (including losses) with `spice-heavy pnpm -C packages/wasm exec tsx scripts/bjt-ac-accuracy.ts` after building.

MOS1 operating points and DC sweeps accept six-token `Mname drain gate source bulk model` instances with optional numeric `W`, `L`, `NRD` and `NRS`. Models are `.model name NMOS(...)` or `PMOS(...)`, with optional `LEVEL=1`, `VTO`, `KP`, `LAMBDA`, `GAMMA`, `PHI` and numeric constant `RD`/`RS`/`RSH`; omitted parameters use core's ngspice-compatible defaults. In OP, DC, transient and AC, series resistance uses core's physical series-resistor/internal-node expansion; each internal node counts against the 64-unknown ceiling. Given nonzero `RD`/`RS` override sheet resistance; otherwise omitted `RD`/`RS` use `RSH*NRD`/`RSH*NRS` (default one square). Zero squares suppress the sheet prime node. As fixed in core #757, explicitly given `RD=0`/`RS=0` with nonzero sheet resistance and squares opens that terminal rather than falling back to sheet resistance. `src/numeric-wasm-mos1-series.test.ts` compares every node voltage and source current with core on 24 original MIT NMOS/PMOS RD-only, RS-only and RD+RS fixtures. `src/numeric-wasm-mos1-rsh.test.ts` adds 64 original MIT NMOS/PMOS fixtures covering drain/source/both sheets, direct-resistance precedence, explicit zero RD, default squares and zero squares across all four analyses, plus 64/65-unknown boundary and structured-rejection tests. Both suites use `1e-9` relative / `1e-12` absolute bounds (AC magnitude/phase: `1e-9` relative) and identical accepted transient time grids. This is bounded core-backend parity evidence, not an ngspice or speed claim. Newton reuses core's MOS1 companion equations, body-junction limiting and convergence checks around the existing WASM linear solve, with the same bounded per-point iteration budget and no fallback. DC sweeps retain device state and warm-start Newton from the previous solution. Other levels/model parameters (including temperature), nonconstant resistance/squares parameters, and unsupported instance options return structured `UNSUPPORTED_FEATURE` (`mosfet-model-parameter` or `mosfet-form`). The numeric kernel/artifact is unchanged.

### Measured cost of this slice

Measured on 2026-10-10 with Node 22.23.1, pnpm 10.28.1, ngspice-47, LLVM/LLD 23.1.3 and an arm64 Apple M5 Pro. The fixed five-circuit AC suite uses byte-identical netlists for both spice-ts backends and ngspice. Its 29 WASM frequency points produced these aggregate rectangular-complex errors:

| Reference | Compared samples | Max absolute | RMS absolute | Max relative | RMS relative |
| --- | ---: | ---: | ---: | ---: | ---: |
| `spice-ts-js` | 64 | 4.4492e-16 | 1.5426e-16 | 1.7826e-15 | 2.9435e-16 |
| ngspice-47 | 63 | 1.1571e-15 | 2.1615e-16 | 1.3279e-15 | 3.7118e-16 |

The identical-netlist LIN regressions match ngspice-47 exactly: N=1 yields `[100]` Hz and N=4 yields `[100, 400, 700, 1000]` Hz. One ngspice endpoint was excluded because its floating frequency landed just below spice-ts's final OCT point; the complete per-fixture grids and every signal metric are retained in `ac-accuracy-results.json`. No zero-reference samples were excluded.

Five samples each ran 20 one-shot worker simulations after five warmups. Median time was 1,490.678 ms for `spice-ts-js` (74.5339 ms/run) and 1,492.458 ms for `spice-ts-wasm` (74.6229 ms/run), a 0.1194% WASM loss. This worker-dominated difference is noise-level and is not a speed claim. The measured size losses are larger: the artifact grows from 1,190 to 2,900 bytes (+143.70%), worker.js from 355,517 to 377,009 bytes (+6.05%), index.js from 41,878 to 42,815 bytes (+2.24%), and their combined uncompressed size grows 24,139 bytes (+6.06%). Larger or sparse circuits cannot use this backend at all.

## Integrity and isolation

`createSpiceEngine` verifies `dist/worker.js` and, for `spice-ts-wasm`, `dist/dense-solver.wasm` against `dist/manifest.json` before constructing a worker. Missing, malformed or mismatched assets fail with `BACKEND_UNAVAILABLE`. Build IDs use the first 16 hexadecimal characters of the selected artifact's SHA-256.

The checked-in numeric artifact is copied during package builds, not rebuilt using an ambient toolchain. Its reviewable C source, pinned regeneration command, expected hash, size and ABI v2 are documented in `native/README.md`. ABI v2 exposes bounded linear VCCS, CCCS, VCVS, and CCVS stamps plus the real and split-complex solver entry points.

The worker receives request values and the already verified numeric bytes only. It exposes no WASI, socket, host-filesystem, clock, randomness or ambient fallback API. Package build and test scripts do not publish or deploy anything.

## Streaming and cancellation

`simulateStream` emits fixed point-count chunks after the one-shot worker returns. OP has no point events. AC arrays are bounded to 1,025 points and DC/transient arrays to 4,096 points before allocation. `cancel(requestId)` terminates the operation's one-shot worker; cancellation before asynchronous worker construction is also registered. Caller wall-time expiry terminates the worker. The fixed 64-unknown ceiling bounds each non-interruptible solve.
